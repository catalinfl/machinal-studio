# Editor reliability and guided workflows

This update builds on existing editing/export paths rather than replacing the Svelte/Pixi/FFmpeg stack.

## Delivered behavior

- **Offline recovery:** missing browser-local originals do not prevent timeline opening. Relink validates kind, dimensions and sufficient duration without changing clip IDs, source windows or caption text/word timing. It checks compatibility, not cryptographic file identity.
- **Assisted export:** the Render dialog shows actual project settings, offline/silent-export warnings, live credit/rate information and an approximate render estimate. Local-source uploads require a separate checkbox and use unique filenames. Successful transfers are reused by File identity in the mounted session; a different relinked File cannot accidentally reuse stale remote bytes. Uploaded exports preserve the current browser-local timeline.
- **Saved versions:** up to 20 named checkpoints / 512 MiB per project, optimistic version checks, restore confirmation and an automatic current-edit checkpoint before replacement. Removal is separately confirmed. Checkpoints reference originals and cannot recover originals that were explicitly deleted.
- **Copies:** project duplication streams server originals into an independent owned workspace and copies available browser-local originals into the new project scope. Partial unpublished copies are cleaned up; existing originals are not changed. A concurrent edit keeps the current workspace open instead of reloading over it.
- **Guided starts:** Captioned reel, My media montage and Narrated video configure the appropriate framing and open existing tools. The dismissible guide progresses from importing or writing speech to arranging, caption review/generation and Render. Choosing a guide is not a generation request.
- **Less job clutter:** export history is the default view, with AI operations kept separately for recovery. Simple new-source scene compilation returns directly using durable free-operation receipts. Source-file edits, handoffs and explicit asynchronous calls retain legacy recovery jobs. Paid/long provider work is not made unsafe merely to reduce the visible job count.
- **Client budget:** delayed capture/serialization for autosave; indexed active-caption lookup; cached fitted layouts; release of inactive caption textures; scoped IndexedDB cursor reads; and an adaptive, preview-only frame/pixel budget for resource-constrained browsers. Export settings and successful captions/assets are unchanged.
- **Caption freeze guard:** an incomplete saved style (including missing/NaN font size) no longer enters unbounded fitting. Invalid numeric input is reported without rewriting saved text/words/timing, and fitting stops after at most 64 attempts. Preview continues and clears the recoverable error after a valid style repair.
- **Provisioning:** cached API queue readiness and local durable Bolt queue recovery (PocketBase provisioning is hosted-only).

Go tests/vet and focused race checks pass, including actual migrations/hooks on a checksum-verified isolated PocketBase 0.23.12 executable. The installer suite has 368 passing tests / 4 platform skips, and all 125 bundled references are synchronized. The documentation/provisioning/module-boundary suite has 29 passing tests; provisioning/backup checks use synthetic files and credentials.

All 29 selected Chromium regressions pass across `editor-reliability`, `project-concurrency`, `projects`, `membership-jobs`, `video-framing`, `image-overlay-export` and `captions`. Coverage includes large-raster project reopening, exact saved caption preservation, offline relinking, guided starts, version restore, upload consent, jobs recovery and encoded crop/image-overlay pixels. The new performance fixture uses 2,000 captions, four-times CPU throttling and an unavailable FontFaceSet. This is emulation, not verification on a physical low-memory device or proof that every reported `f.fontFamily` stack trace has the same cause.

The five editor-reliability scenarios also pass with the existing storage notice acknowledged in the synthetic fixture. Their fresh desktop/mobile captures were visually inspected for offline recovery, saved versions, export consent and the large-caption timeline; evidence is retained under `client/test-results/editor-final-review/`. Incidental tracked PNG changes from older tests were restored, with their current evidence preserved under `client/test-results/final-review-evidence/`. This is a scoped state/layout check, not whole-product visual certification.

No production deployment, customer-media access, purchases or paid generation/rendering are part of these checks. The optional PocketBase Compose configuration is validated; the Docker image build and a real production restore remain operator checks. Queue readiness does not certify providers, payments, S3 or the scene renderer. Apply matching API/client changes together after staging and coordinated backups.
