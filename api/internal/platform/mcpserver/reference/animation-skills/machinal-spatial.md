# Spatial direction

The current client writes and repairs complete source; no server-model fallback or local production renderer.

Use real `SceneThree` with the deployed runtime API; read `scene-runtime` and one spatial template before source. CSS perspective on a raster is not 3D reconstruction. Use 2D if spatial depth adds no understanding. Do not reuse an unrelated demo primitive as the whole subject.

1. Block the meaningful parts first. Identify which part is fixed, which drives and which follows. Choose dimensions/axes from supplied facts or explicitly schematic geometry; never invent real product internals.
2. Compose the main action in a three-quarter view with separation along functional axes. The camera must see the relationship before orbiting. A fixed camera is often clearer than perpetual orbit.
3. Frame for the actual aspect and caption-safe region. Keep near/far planes and the complete moving bounds inside the frustum at reveal/action/hold. Test portrait separately; do not merely crop the landscape camera.
4. Give light a job: a key defines form, fill preserves readable shadows, rim separates a dark edge. Use restrained palette/material contrast so the functional part attracts attention. Inspect for washed-out metal, black faces and excessive transparent layers.
5. Derive every position, rotation, visibility and camera target from absolute frame state, including defaults before/after the action. No accumulation, independent render loops or clock-driven physics.
6. Retain clear silhouettes through the central hold. Move objects independently where meaning requires it; camera motion alone is not mechanical action.

For approved static GLB models use tracked async `loadSceneModel`; textures use `loadSceneTexture`. Keep the current two-model/4 MiB limits and self-contained static GLB subset. Do not invent skinning, imported animation, decoders or model generation. A missing suitable model requires an honest medium choice or separately approved asset scope, not a hidden provider fallback.

Register deterministic object states only if they correspond to the visible geometry. `handoff_scene` copies registered values into exposed incoming parameters; it does not infer camera/unit conversion. Inspect the boundary frames after the handoff. Keep camera, origin, axis and scale semantics compatible.

Use approved `inspect_scene` samples for aspect, silhouette, occlusion and lighting. Thumbnail samples do not prove subpixel text quality, smooth camera motion or final compositing. No claim of visual approval from source compilation.

Use the native question tool only for a missing new-video brief, not a numbered chat questionnaire. A cancelled form grants no scope. After actual authorization proceed immediately without a separate plan confirmation. Preserve caption/audio/assets; source compilation is free, server rendering and providers are not. Never add unrequested audio or paid preview work.
