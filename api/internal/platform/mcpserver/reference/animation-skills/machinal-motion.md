# Motion direction

Use the existing machinal engine and current-client source authoring. Read `scene-runtime` and the exact selected template/style. No external runtime, server model or local production renderer.

## Commit to a visible idea

1. Write one sentence: **subject → action → changed understanding**. If changing the heading makes the same scene fit any topic, redesign it.
2. Separate reference roles: look controls palette/material/light; motion controls a particular mechanism or camera move; assets are the actual approved subject. State exactly which beat uses which quality. Existing user references take precedence; no arbitrary reference count or mandatory browsing. A still does not demonstrate motion.
3. Consider two concise staging ideas in text, choose the clearer one, implement only it. This does not authorize generating alternative paid assets.
4. Choose the medium by the subject: Svelte/SVG for truthful diagrams; approved raster cutouts for detailed subjects; genuine SceneThree for spatial relationships; approved footage for complex realistic action. Never turn every subject into rounded cards, a spinning cube or a single-image zoom.
5. Design one main transformation for an expressive beat: separation reveals assembly, an occluder exposes a relevant detail, a route joins known places, or two supplied states align for comparison. Minimal briefs may need only a quiet hold. No invented facts, maps or 3D reconstruction inside flat photos.
6. Make the hero recognizable at thumbnail size, with foreground/midground/background only where meaningful. Reserve the existing caption band. Short labels support the subject; they do not replace it.

## Compact shot contract

Record measured start/end, supplied message, actual asset IDs, independent objects, reveal/action/hold/exit times, camera, next-shot relationship and evidence needed. Distinguish global timeline time from scene-local seconds and normalized progress. Keep source-level artwork choices separate from supported exposed parameter fields.

Example: an approved transparent product lands; a supplied detail crop moves independently beside it; the connector remains attached as the product turns in **2D**; both settle for reading. This is not reconstruction of hidden product geometry. A mechanism instead needs the actual relevant schematic parts and causal linked movement, not that same product treatment with another title.

After compilation use `plan_scene_review` with actual output fps/duration and action phases. Inspect approved frames; close major findings with a targeted patch, preserving ambition, artwork and successful audio/captions. Do not add movement merely to pass a motion check.

## Permissions and continuity

For an incomplete new-video brief use the host native question tool in one form, not a numbered chat questionnaire. A cancelled form grants no permission. With the agreed authorized scope, proceed immediately without a separate plan confirmation. Reuse approvals; ask only for missing scope, a hard budget or a blocker. Never add unrequested narration/captions/music/sound effects. Preserve exact caption entries, timings, IDs and styling. Source compilation is free; provider assets, server scene frames and final encoding retain normal approval/billing.
