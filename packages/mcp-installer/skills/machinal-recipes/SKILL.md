# Schema-grounded video recipes

**TikTok caption font.** When the brief targets TikTok or requests TikTok-style captions, NEW captions explicitly use `fontFamily: montserrat` and `fontWeight: 700`, unless the user explicitly chooses another font. Verify the deployed `fonts` entry; Montserrat is the supported TikTok-style choice, not official TikTok Sans. Set both fields in `captions.generate.style` before the timing-first pass, or flattened on newly authored manual captions; a `tiktok-pop`/`tiktok-box`/`tiktok-glow` preset name alone is not enough. Preserve existing caption fonts/configuration unless a font change is explicitly requested. Generic portrait/social output does not imply TikTok or authorize adding captions. Read `references/text-audio.md`.

**Existing captions are read-only.** Unless the user explicitly requests a caption change, preserve complete caption entries: exact `texts[].text`/`words[].text` (spaces, line breaks, punctuation, diacritics), grouping/order, IDs/`resultTextIds`, source anchors, timings, positions/fonts and all style, animation/highlighting/effects. Do not reword, trim, split/merge/reflow, reposition or restyle them while adding visuals or repairing unrelated fields. Existing caption configuration overrides style/profile/`captionMaxWords` defaults; four-word/two-line defaults apply only to NEW caption generation. The renderer handles fitting/wrapping/collision avoidance: adapt scene labels around captions, not captions around scenes; never bake/duplicate them into Svelte. Patch resolved `recipeYaml`, use `sourceJobId` for unchanged continuation, and compare complete caption entries against that baseline before submission; undo unintended changes. Validation alone does not prove preservation. Read `references/text-audio.md` for encoding-only repair exceptions; report genuine blockers and ask before other caption changes. This is not a new YAML lock flag.

**Verify the promised edit.** Use `machinal-review` and `get_editing_reference(topic: production)` for the production contract/pre-code critic and final source/plan review. `compile_recipe` adds `editorialReview` with actual junctions and resolved treatments; compare it with the contract before rendering and implement omitted promised accents. `review_required` is not aesthetic approval, and no recipe-level effect does not mean no scene-internal effect. Keep the existing scene-engine and normal approval/preflight rules.

**Approximate runtime follows narration.** Treat requested or AI-proposed runtime as approximate unless the user explicitly sets a hard duration cap. For a planned 30-second video with 38–40 seconds of successful narration, keep the voice/captions and extend the video to the measured narration end. Lengthen/recompile existing scenes and holds or add relevant client-authored scenes within the approved visual scope; update placements and transition overlaps to cover all speech. Do not regenerate, truncate or speed up narration solely to meet an estimate, or rerun successful captions/images. State the adjusted runtime and continue without reconfirmation within existing permissions. Resolve an explicit hard duration cap or spending limit before changing paid narration or exceeding approval. Read the jobs/scenes reference for asset-duration limits and retiming.

For image-led videos, image sourcing is not presentation: if undecided, use `machinal-editing` to ask once whether images may be integrated into animated Svelte scenes, including genuine Three.js when spatial storytelling helps. Reuse explicit answers/delegation; preserve still-only/no-scenes/no-generation constraints and keep standalone image searches in scope. Use `machinal-scenes` for a subject-specific signature visual action, then implement the approved **effect score** on actual resolved tracks/clip IDs and verify it survives final validation. These are planning concepts, not YAML fields or permission to spend.

Before authoring a new video, use `machinal-editing` and `get_editing_reference(topic: brief)` (offline: `../machinal-editing/references/brief.md`). Ask about missing type/goal, duration, aspect/output resolution, visual sources/style and audio/text using the host's native question tool (OpenCode: `question`), with one `questions` array and concrete options, not a numbered chat questionnaire; wait for the user's reply. Recommend relevant image/scene/footage choices in that same form. Use an unnumbered chat fallback only if no interactive tool is available. After the user answers, summarize briefly and proceed immediately with authorized work in the same turn, without a separate plan confirmation or approval of each covered stage. Include known permissions as separate explicit questions in the same form where possible; reuse actual permission for the same scope, never infer it from creative choices or a cancelled form. Ask again only for a genuine blocker, changed scope or missing permission. Do not re-ask answered questions or force a questionnaire for a complete brief, small edit or “you decide” delegation. Do not automatically add production labels to titles/captions or repeat them in chat; be honest about generated media and agree once on any requested or specifically required disclosure. Brief choices do not authorize media access or spending.

1. Read `get_editing_reference(topic: yaml)`, `get_recipe_schema` and compact `get_capabilities` once; cache them until schemaHash changes. The schema is for `document`, while the composition envelope has sibling `bindings`, `assets`, optional `snapshot`/`preparedText`. Use targeted references, not repeated full-catalog reads. The live contract wins over offline snapshots.
2. Fetch a complete matching example through `get_editing_reference(topic: examples, id: ...)` or read `references/examples.md` and `references/examples/`. They are compiler-tested synthetic fixtures, not source media, transcripts or revisions in the user's account. Replace example-only metadata with real values; pending examples never authorize provider execution.
3. Select an owned project. Ask for permission before listing existing/cloud media (`request_media_access` prepares the question, not the approval). Then use `list_media(userApproved:true, storage:s3|volume|all)` and follow `nextOffset`. Ask separately before inspecting/using named files with `get_asset_metadata(userApproved:true)`; listing consent does not authorize downloads, use or spending. Preserve unrelated fields, source choices and explicit presets. Use matching IDs, real source handles and correct source versus timeline times; account for overlap subtraction in total duration.
4. Use `machinal-editing` for exact catalog treatments. Evaluate footage/still/scene per beat. The CURRENT client AI writes Svelte CODE and calls `compile_scene`; read scene-authoring/scene-runtime and example client-scene. Place its returned live source asset in video tracks, not a pending scene.generate/scene.edit job or inline Svelte YAML. No server-model fallback is allowed. Client-authored code avoids the server AI fee, but server scene frame rendering AND final video encoding remain billed at the configured rendering rate, alongside images/TTS/captions. Source compilation is not a rendered scene video. Author `.edit.yaml`, NOT JSON. For narrated work use a timing-first pass: generate_assets with speech (language ro/en), its audio placement and requested captions only, no image/scene jobs. Wait for status=completed and get_job_result before deriving image holds, 2D/Three.js cues, durations and placements. Preserve speech resultAssetId, caption resultTextIds, actual texts/words and assets in the edited YAML. Adding visuals needs edited composition, not unchanged sourceJobId. Read narration-timing; narrated-documentary is a legacy server-scene example to adapt to compiled assets. Reuse approved timing; do not add unrequested TTS/captions or invent word times. A failed timing pass blocks visuals. No imaginary presets.
5. Read topical references as needed: `references/commands.md` for selectors/patch operands; `references/text-audio.md` for flattened text style, verified word timing, registered fonts and percent audio volume; `references/jobs-scenes.md` for supported stages/generation fields. Caption job `style` is a supported TextStyle patch, not a text preset name or arbitrary CSS.
6. Supply the complete composition **string** to `validate_recipe` after every edit, not a local path; before final `render_video`, that exact YAML must have no error diagnostics or unresolved requirements. Pending generation means timeline geometry needs validation again after materialization. Include pinned source metadata; use `compile_recipe` to inspect the normalized result/duration and keep all requested final treatments. Preserve resolved documents/assets and patch only affected fields; write valid YAML directly or use an existing serializer, never an ad-hoc YAML emitter. `version` is numeric; optional `catalogVersion`/`compilerVersion` are strings (quote deployed values such as `'1'`, never numeric `1`, or omit unneeded pins). `tracks`/`clips`/`transitions`/`texts`/`words`/`assets` are lists. Clip `outPoint` is source time: `outPoint = inPoint + timelineDuration * playbackRate`, not the timeline end. Verify each overlap from actual clip ends at microsecond precision. Never use paid rendering to discover syntax/type/overlap errors. `draft: true` or pending requirements do not prove a finished render.
7. For local-folder/no-upload requests discover `list_local_media`: configured owner-scoped read-only roots support `inspect_local_media` thumbnails and `import_local_media` independent project working copies without network/S3 upload. These require their actual inspection/use approvals, never arbitrary paths or deployment changes. Use returned project filenames, pin inspected sourceVersion values and keep originals untouched. Otherwise upload new local media separately with `get_upload_target` and an approved authenticated REST transfer directly to the persistent volume, not S3. Approved existing S3 files hydrate into that volume for processing. A loopback MCP URL alone still cannot resolve arbitrary local client paths, URLs or binary/base64 YAML.
8. Enumerate pending provider actions, check live credits and get explicit source-use/spending authorization before `generate_assets`/`render_video(userApproved:true)`. Keep returned resolved assets/documents, then finish/revalidate treatments on actual track IDs after generation. Inspect jobs/media before new paid work and reuse stable exact-operation idempotency keys.
9. After completion and receiving approval, `get_video_result(delivery:link,userApproved:true)` returns an opaque one-hour application download link: give the requested clickable link/expiry, not raw S3 credentials or a local path. Only an explicitly requested client-local file uses `delivery:local` and approved download preferences; ask if unset, never overwrite and verify the full file. The Docker/server volume is not the client's filesystem and the server never writes to that client directory. Never attach the application key to links/redirects, print underlying signed S3 URLs or embed them in visible commands. Permission flags report an actual user reply; never self-approve.

`save_project` is separate: it needs the complete editor state and current version, not YAML. Preserve all fields and reconcile 409 conflicts. Keep API keys, authorization headers and private credential paths out of recipes, filenames, output and chat.

Keep generation, scene compilation, text preparation and rendering in Directional. Do not build local Python/FFmpeg pipelines or HTTP bridges. For unchanged continuation use sourceJobId; use get_job_result once for resolved recipeYaml when editing is needed. Prefer wait_for_job(timeoutSeconds:120), not repetitive progress lookups or sleep scripts. For left-edge titles use anchor:left and align:left; x/y are design pixels, not percentages. Preserve the approved final delivery separately from processing-location preferences. Do not promise music generation when capabilities say unsupported. Scene YAML prompts are concrete storyboards, not generic headings or vague CSS: specify subject/action, medium, composition/depth, palette/light, exact copy and local reveal/action/hold/exit. Use visualMode:3d with real SceneThree for requested spatial scenes. Never put AI-production labels/disclaimers/watermarks on screen, including in image prompts or textures.
