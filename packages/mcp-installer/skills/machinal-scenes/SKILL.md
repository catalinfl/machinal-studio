# Plan footage, stills and animated Svelte scenes

**Film-style library.** Use `machinal-cinema` for 66 cinematic visual languages and directing/helpers reference. Discover `film-styles`/`film-techniques`; native `scene-templates` now include `swiss-grid-motion`, `blueprint-mechanism` and `paper-stage-3d`. Adapt real subject/action/material/camera, not just the demo label. The imported sources do not authorize local rendering, media access, caption changes or paid work; existing runtime and production-review rules win.

**Visual coverage, not minimum cost.** Overly simplistic SVG/CSS is also a reason to use images. For documentary/biography work, plan distinct people, geographic context, environments and period-grounded illustrative scenes from verified copy rather than one reused portrait plus text, lines and nodes. Keep an image-coverage list linking each asset to its measured beat, purpose and scene. 5–10 distinct images per video can be appropriate, not a quota or cap; the four-image attachment limit is per scene, not per video. Reuse suitable successful assets, but do not simplify solely to make the video cheap. Respect the approved budget and ask if necessary coverage exceeds it; minimal/no-generation/procedural-only briefs still win. `image.generate` is a YAML job type, not an MCP tool: select `generate_assets` for approved missing artwork after the timing-first checkpoint, then `wait_for_job` and `get_job_result` before composing its actual filenames with `compile_scene`. Tool selection grants no consent and does not authorize changes to narration, captions, pacing or transitions. See `references/workflow.md` for coverage and tool-selection details.

**Complex assets and transparent cutouts by default.** If a character, animal, plant, realistic product or detailed illustration would not read well as SVG/CSS, default to an image-backed animated scene: reuse an approved suitable image or plan `image.generate` within approved generation/spending scope, without waiting for an explicit image request. For isolated foreground subjects/sprites and separately composited layers, default to `background: transparent` with `openai/gpt-image-2.5-sunburst`; `openai/gpt-image-2.5-flare` also supports transparency. Respect explicit model choices; keep full-frame environments `background: opaque`, simple diagrams procedural and spatial action genuine SceneThree. Request real alpha and clean edges, no painted checkerboard/backdrop or baked-in labels. Wait for the actual generated filename, attach through `compile_scene.images`, preserve PNG/WebP alpha and animate separate approved layers/labels within the four-image limit. `compile_scene.transparent` controls the canvas, not the image background. Do not claim alpha is verified from the request/metadata/JPEG thumbnail, automatically regenerate paid assets, or bypass no-generation, footage-only, `imagePolicy: procedural-only` and consent boundaries. Reuse existing scope approvals. See `references/workflow.md`, section "Complex scene assets: images and transparency by default".

**Reusable effect examples:** Before authoring an effect from scratch, discover `get_editing_reference(topic: scene-templates)` and fetch a relevant `id` for complete editable Svelte source, source-level parameters, required images and choreography. Offline: `references/scene-templates.md`, `references/scene-templates.json` and `references/scene-templates/*.svelte`. Adapt the selected technique to the actual subject, supplied copy, measured timing and output aspect; do not merely rename unrelated demo geometry or force a template into every scene. These are persistent examples, not model training, YAML presets or new compile_scene arguments. Keep source-use/spending approvals and the usual compile_scene workflow; live deployed examples take precedence.

**Existing captions are read-only.** Unless the user explicitly requests a caption change, preserve complete caption entries: exact text/word spacing and line breaks, grouping/order, IDs/`resultTextIds`, timings, positions/fonts and all style, animation/highlighting/effects. Do not reword, split/merge/reflow, move or resize them to fix a scene collision. The renderer handles caption fitting/wrapping/collision avoidance; adapt scene labels around the existing caption band, never change or bake/duplicate captions into Svelte. Existing caption configuration overrides style/profile/`captionMaxWords` defaults; four-word/two-line defaults apply only to NEW caption generation. Compare complete caption entries against the resolved YAML baseline before submission; undo unintended changes. Validation alone does not prove preservation. Read `../machinal-recipes/references/text-audio.md` for encoding-only repair exceptions; report genuine blockers and ask before other caption changes.

**Director → critic → builder → critic.** After the brief, read `get_editing_reference(topic: production)` (offline: `../machinal-review/references/production.md`) and use `machinal-review`. Define the production contract and challenge subject specificity, independent motion, staging and handoffs before scene code. Before rendering compare the source and actual `compile_recipe.editorialReview` with promised treatments. Do not confuse successful compilation with aesthetic approval. Keep the existing scene-engine; no Remotion migration, server critic or unapproved paid review loop.

**Controlled assets and continuity (check deployed capabilities first).** `compile_scene.models` accepts two approved self-contained static GLB v2 files, 4 MiB each, one scene and embedded PNG textures; no external URIs/extensions/decoders/imported animations/skins/morphs. Upload to the owned project volume, then use actual filenames and tracked `loadSceneModel`/`loadSceneTexture` in async SceneThree setup. Read `references/runtime.md` for full bounds; never invent a conversion/generation fallback. `handoff_scene` samples deterministic registered `scene.objects` state at an exact outgoing frame and patches exposed incoming parameter IDs; both named scenes/versions require source/edit consent. It creates a new immutable asset, preserves incoming timing and all media/audio, does not infer pixels/convert camera coordinates or replace timeline references. Read `references/authoring.md`. Compilation/diagnostic inspection is free; rendering is still billed. `placeAnchoredLabel` is a bounded rectangular candidate search, not a universal constraint solver or permission to reflow captions. Verify actual output; registered declarations do not prove visual continuity.

**Approximate runtime follows narration.** Treat requested or AI-proposed runtime as approximate unless the user explicitly sets a hard duration cap. For a planned 30-second video with 38–40 seconds of successful narration, keep the voice/captions and extend the video to the measured narration end. Lengthen/recompile existing scenes and holds or add relevant client-authored scenes within the approved visual scope; update placements and transition overlaps to cover all speech. Do not regenerate, truncate or speed up narration solely to meet an estimate, or rerun successful captions/images. State the adjusted runtime and continue without reconfirmation within existing permissions. Resolve an explicit hard duration cap or spending limit before changing paid narration or exceeding approval. Read the jobs/scenes reference for asset-duration limits and retiming.

For a new video with an incomplete brief, first use `machinal-editing` and `get_editing_reference(topic: brief)` (offline: `../machinal-editing/references/brief.md`). Ask about missing type/goal, duration, aspect/output resolution, visual style/materials and audio using the host's native question tool (OpenCode: `question`), with one `questions` array and concrete options, not a numbered chat questionnaire; wait for the user's reply. Recommend 1–2 relevant existing-photo, generated-image or animated-scene options in that same form. Use an unnumbered chat fallback only if no interactive tool is available. After the user answers, summarize briefly and proceed immediately with authorized work in the same turn, without a separate plan confirmation or approval of each covered stage. Include known permissions as separate explicit questions in the same form where possible; reuse actual permission for the same scope, never infer it from creative choices or a cancelled form. Ask again only for a genuine blocker, changed scope or missing permission. Do not re-ask answered questions or override “you decide” delegation. Do not automatically add production labels to scenes/captions or repeat them in chat. Be honest about generated media and resolve any requested or specifically required disclosure once. Creative choices do not authorize paid work.
