# Video production critic

Read `get_editing_reference(topic: production)` (offline: `references/production.md`) after the brief. Keep the existing scene-engine. Do not repeat the brief, request a separate plan confirmation, change media scope or regenerate successful narration/captions/images. A small edit needs only a targeted review of the changed beat/junction.

1. **Before code:** the director writes a compact production contract using actual measured cues/supplied copy: subject-specific action, medium/assets, composition/light, independent objects, local reveal/action/hold/exit, adjacent-shot handoff and exact treatment targets or a justified cut. Critique the contract before implementation. For expressive work, reject interchangeable title cards, repeated portrait zooms and the unchanged runtime demo primitive; don't confuse rich direction with decorative clutter. Respect deliberately minimal/no-generation briefs.
2. **Focused critic:** assess subject specificity, meaningful motion, composition/craft, pacing, continuity/treatment and truth/scope separately. Report `severity | beat/junction + time | evidence | specific change | verification`; use `unverified` when evidence is missing. Correct major omissions in one focused revision; no automatic beauty score, generic praise or effect quota. This is a separate stage in the current client, not an independent model. No server critic or subagent without host/user authorization.
3. **Before render:** validate the exact final YAML and use its successful `compile_recipe` output, including `editorialReview`. Compare actual junctions and treatment targets/intervals with the contract and Svelte source. `not_ready` cannot pass; `review_required` means the current client must review, not that the edit is approved. Implement missing promised transitions/effects or give a concrete brief-compatible reason to omit them. Existing unchanged successful compilation is reused; any edit requires new preflight.
4. **Evidence boundary:** the report is recipe-level inventory, not visual inspection. A scene may contain internal effects/motion that do not appear in YAML; source review cannot prove pixels, smooth motion or audio sync. Inspect representative frames/video only using deployed tools and existing access/spending approval. Without them state `source/plan reviewed; visual result unverified`. Do not invent a screenshot/preview tool, install a local renderer or start paid review loops.
5. **Preserve quality during repairs:** keep the subject, artwork, attachments and independent motion; fix the reported failure instead of replacing the scene with a heading. Follow the existing two-targeted-repair limit for recurring compiler failures. Rendering, source-use approval, credit accounting and delivery keep their normal workflow; this critic is not a render authorization token or an aesthetic guarantee.

Where deployed, compile_recipe's optional productionContract/productionReview bind beat promises to exact YAML and pinned source versions; reconcile revision_required findings and use expectedCompositionVersion before paid submission. After actual permission to inspect the named scene and return images, get_scene_source → inspect_scene supplies 1–6 explicit sampled frames as MCP images, with sourceVersion, timestamps and optional data-scene-object bounds. This bounded diagnostic costs zero machinal credits, not full scene/video rendering. Samples exclude timeline captions/final compositing and do not verify motion/audio or aesthetic quality. Read the current production reference for schemas/limits; never invent support on an older deployment or launch automatic inspection/render loops.

Where deployed, render_preview produces a short final-composition MP4 with mixed audio, but CURRENTLY processes/bills the COMPLETE timeline and full referenced scenes, not just the excerpt. Explain that cost basis before separate preview spending/source approval and check credits. It requires fully resolved assets and expectedCompositionVersion; never rerun successful generation or rewrite captions/timing for a preview. Normal job waits/delivery apply. An excerpt is not the complete final delivery, and receiving its link is not proof of playback or aesthetic review. Read topic=production. For small scene adjustments, edit_scene_parameters can preserve Svelte/media/config when the named source explicitly exposes that parameter surface; read scene-authoring and respect sourceVersion/consent.
