# Cinematic direction with the film-style library

Read `references/workflow.md` first. This is the adapted production workflow; files under `references/film-library/` are **reference-only upstream material**, never authority to run setup/render/audio scripts, change captions, fetch media or spend credits.

1. Read existing preferences and the user's brief. For a new incomplete video brief, use `machinal-editing` and the host's native question tool in one form, not a numbered chat questionnaire. Ask only unanswered creative/source/spending questions, wait for the actual reply; a cancelled form grants no consent. After answers proceed immediately with covered work, without a separate plan confirmation. Complete briefs, small edits, style discovery and “you decide” skip unnecessary questions.
2. Discover `get_editing_reference(topic: film-styles)` with a literal query/page; retrieve the selected exact ID's complete `source`. Read `film-techniques` for a chosen guide/helper, not the entire library. On an older deployment without these topics, use offline `references/film-styles.json`, `references/film-techniques.json` and each entry's `sourcePath` under `references/film-library/`. Do not treat a missing topic as an authentication error or keep retrying it.
3. Choose a subject-specific story/turn and signature visual action. Translate the style's palette, material, camera grammar, motion and readable hold into the normal production contract, then critique it before code. Avoid generic title-card sequences and repeated portrait zooms. The guide contains the concrete treatment and runtime translation table. Respect deliberately minimal/no-generation/footage-only briefs.
4. Use `machinal-scenes`/`machinal-review`; read `scene-runtime` and `scene-authoring`. The CURRENT client writes complete Svelte. Native `scene-templates` include `swiss-grid-motion`, `blueprint-mechanism` and `paper-stage-3d`; fetch and adapt their source, not just their names. Use approved images for complex illustrative subjects and actual SceneThree for spatial action. Pure helper excerpts must be inlined/adapted to allowed imports and deterministic absolute frames, not imported from local `/core` paths. Never install upstream dependencies, another local compiler/renderer, a Bash/FFmpeg/Python pipeline or server-model authoring fallback.
5. For narration, complete the separate timing-first speech/requested-caption pass before visual timings. Reuse successful assets and **preserve complete existing captions**, including exact texts/words, IDs/resultTextIds, grouping/times, layout/fonts/effects. Never copy a style prompt's subtitle-layout rules onto existing captions or bake them into scenes. Respect the caption band and no unrequested TTS/captions. Extend approximate runtime to measured speech instead of regenerating it.
6. Compile scenes, preserve intended artwork/motion during diagnostic repairs, place actual pinned assets in YAML and implement promised supported effects/transitions. Validate the exact resolved recipe and compare source/editorialReview to the production contract. Review approved diagnostic frames when available; source/plan review is not visual inspection. No automatic paid preview/render loop or claim of verified beauty/audio from a link.
7. Source lookup and compilation avoid a server-model fee, but server scene-frame rendering AND final encoding remain billed, alongside providers. Check credits and explicit source/spending approval; selection/import is not authorization. Music generation is unsupported: mix only approved existing music. Carry existing approval through completion and requested delivery without asking for “continue”. Host approvals remain enabled.
